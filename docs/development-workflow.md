# Рабочий процесс команды

1. **Зафиксировать контракт** — типы, единицы, ошибки и критерии завершения.
2. **Разрабатывать независимо** — участники работают в отдельных ветках и не редактируют один и тот же модуль без координации.
3. **Проверить контракт** — одинаковые тесты для всех реализаций одного интерфейса.
4. **Оценить на одинаковых сценариях** — фиксировать commit SHA, конфигурацию, условия, успешность, время и ошибки.
5. **Выбрать победителя** — по заранее согласованным метрикам, а не по субъективному впечатлению.
6. **Интегрировать** — выбрать реализацию конфигурацией; `main.py` не должен содержать ветвление по конкретным алгоритмам.

## Предлагаемые метрики
- доля правильно обнаруженных маркеров по цвету;
- точность подсчёта маркеров на участке;
- ошибка оценки координат;
- успешность доставки и подтверждения готовности;
- доля корректно обработанных красных маркеров;
- длительность этапов и всей попытки;
- число тайм-аутов/потерянных сообщений.

Результаты сравнения сохраняйте в `docs/experiments/` или в согласованном формате CSV/JSON. Не коммитьте видеозаписи и большие логи без необходимости.
